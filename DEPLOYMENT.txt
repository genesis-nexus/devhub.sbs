================================================================================
                    DevHub.sbs - Deployment Guide
                    Multi-Site Nginx Reverse Proxy on Ubuntu
================================================================================

OVERVIEW
--------
This guide explains how to deploy DevHub.sbs and other websites using a
multi-site Nginx reverse proxy architecture. The setup supports:
- Multiple static websites on different domains
- Reverse proxying to backend applications
- SSL/TLS with Let's Encrypt
- Easy site management with a single command

For detailed multi-site documentation, see: MULTI-SITE-GUIDE.md

PREREQUISITES
-------------
1. Ubuntu Server 20.04 or newer
2. Root or sudo access
3. Website files located at: /var/www/devhub.sbs/docs/
4. Ports 80 and 443 accessible (firewall configured)

FILE STRUCTURE ON SERVER
------------------------
/var/www/devhub.sbs/
└── docs/                    # Your static website files
    ├── index.html
    ├── styles.css
    ├── script.js
    ├── blog/
    └── ...

PROJECT STRUCTURE
-----------------
nginx/
├── nginx.conf                    # Main Nginx config (global settings)
├── default.conf                  # Default/catch-all server
├── devhub.conf                   # DevHub.sbs site configuration
└── templates/                    # Configuration templates
    ├── site-static.conf.template      # Static site template
    ├── site-static-ssl.conf.template  # Static site with SSL
    ├── site-proxy.conf.template       # Reverse proxy template
    └── site-proxy-ssl.conf.template   # Reverse proxy with SSL

scripts/
├── setup-nginx.sh               # Initial multi-site setup
└── manage-site.sh               # Site management script

DEPLOYMENT METHODS
------------------

Method 1: Using the Setup Script (Recommended)
-----------------------------------------------
The setup script automates the entire process and installs the multi-site
architecture with devhub.sbs as the first site.

1. Copy files to your server:

   scp -r . user@your-server:/var/www/devhub.sbs/

2. SSH to your server:

   ssh user@your-server

3. Run the setup script:

   cd /var/www/devhub.sbs
   sudo ./scripts/setup-nginx.sh

4. Access your website:

   http://YOUR_SERVER_IP  (default page if domain not configured)
   http://devhub.sbs      (when DNS is configured)

5. Add more sites as needed:

   sudo manage-site add myblog --domain blog.example.com --type static
   sudo manage-site add api --domain api.example.com --type proxy --upstream 127.0.0.1:3000

Method 2: Manual Setup
----------------------
For those who prefer manual configuration:

Step 1: Install Nginx

   sudo apt update
   sudo apt install nginx

Step 2: Install multi-site configuration

   sudo cp nginx/nginx.conf /etc/nginx/nginx.conf
   sudo cp nginx/default.conf /etc/nginx/sites-available/00-default.conf
   sudo cp nginx/devhub.conf /etc/nginx/sites-available/devhub.conf

Step 3: Enable sites

   sudo rm /etc/nginx/sites-enabled/default
   sudo ln -s /etc/nginx/sites-available/00-default.conf /etc/nginx/sites-enabled/
   sudo ln -s /etc/nginx/sites-available/devhub.conf /etc/nginx/sites-enabled/

Step 4: Set correct permissions

   sudo chown -R www-data:www-data /var/www/devhub.sbs
   sudo find /var/www/devhub.sbs/docs -type f -exec chmod 644 {} \;
   sudo find /var/www/devhub.sbs/docs -type d -exec chmod 755 {} \;

Step 5: Test and reload Nginx

   sudo nginx -t
   sudo systemctl reload nginx
   sudo systemctl enable nginx

Step 6: Configure firewall

   sudo ufw allow 'Nginx Full'

MULTI-SITE MANAGEMENT
---------------------
After initial setup, use the manage-site script to add more websites:

Add a static website:
   sudo manage-site add myblog --domain blog.example.com

Add a reverse proxy:
   sudo manage-site add api --domain api.example.com --type proxy --upstream 127.0.0.1:3000

Add with SSL:
   sudo manage-site add secure --domain secure.example.com --ssl

List all sites:
   sudo manage-site list

Disable a site:
   sudo manage-site disable mysite

Enable a site:
   sudo manage-site enable mysite

Remove a site:
   sudo manage-site remove mysite

Check site status:
   sudo manage-site status mysite

NGINX CONFIGURATION DETAILS
----------------------------
Location: /etc/nginx/sites-available/devhub.conf

Key Features:
- Specific domain binding (server_name devhub.sbs www.devhub.sbs)
- Separate configuration per site
- root: /var/www/devhub.sbs/docs
- Gzip compression (in main nginx.conf)
- Static asset caching (1 year)
- Security headers included
- Hidden files blocked
- Per-site logging

ACCESSING YOUR SITE
-------------------
With the multi-site architecture:

- Direct IP access shows the default page (from 00-default.conf)
- Domain access (http://devhub.sbs) shows your site
- Each domain is routed to its specific configuration

VERIFICATION
------------
After deployment, verify everything works:

1. Check Nginx is running:
   sudo systemctl status nginx

2. Test configuration:
   sudo nginx -t

3. List enabled sites:
   sudo manage-site list

4. Test from server itself:
   curl -I http://localhost

5. Get your server IP:
   hostname -I | awk '{print $1}'

6. Access from browser:
   http://YOUR_SERVER_IP  (shows default page)
   http://devhub.sbs      (shows devhub site)

UPDATING WEBSITE CONTENT
------------------------
To update your website files:

1. Upload new files to /var/www/devhub.sbs/docs/
2. Ensure correct permissions (owned by www-data)
3. No Nginx restart needed for static file changes

ADDING A NEW WEBSITE
--------------------
To add a new website to the proxy:

1. Add the site:
   sudo manage-site add newsite --domain newsite.com --type static

2. Copy your website files:
   sudo cp -r /path/to/your/files/* /var/www/newsite/

3. Set permissions:
   sudo chown -R www-data:www-data /var/www/newsite

4. Configure DNS to point newsite.com to your server IP

5. (Optional) Add SSL:
   sudo certbot certonly --nginx -d newsite.com
   sudo manage-site remove newsite
   sudo manage-site add newsite --domain newsite.com --ssl

FIREWALL CONFIGURATION
----------------------
Ubuntu (UFW):
   sudo ufw allow 'Nginx Full'  # Opens both 80 and 443

Cloud Provider Firewalls:
If using AWS, DigitalOcean, Google Cloud, or Azure, you must ALSO
configure their firewall/security groups to allow HTTP (80) and HTTPS (443).

AWS:         EC2 → Security Groups → Inbound Rules → HTTP (80), HTTPS (443)
DigitalOcean: Networking → Firewalls → Inbound Rules → HTTP, HTTPS
Google Cloud: VPC Network → Firewall Rules → tcp:80,443
Azure:       Network Security Groups → Inbound Rules → HTTP, HTTPS

TROUBLESHOOTING
---------------

Issue: Cannot access website
Solution:
  1. Check Nginx is running: sudo systemctl status nginx
  2. Check firewall: sudo ufw status
  3. Check cloud provider firewall (if applicable)
  4. Test locally: curl http://localhost
  5. Check site is enabled: sudo manage-site status sitename

Issue: 403 Forbidden
Solution:
  1. Check permissions: ls -la /var/www/sitename/
  2. Fix ownership: sudo chown -R www-data:www-data /var/www/sitename
  3. Fix permissions: sudo chmod -R 755 /var/www/sitename

Issue: 502 Bad Gateway (for proxies)
Solution:
  1. Check backend is running: curl http://127.0.0.1:PORT
  2. Check error logs: sudo tail -50 /var/log/nginx/sitename-error.log
  3. Verify upstream configuration

Issue: Configuration test fails
Solution:
  1. Check syntax: sudo nginx -t
  2. Review configuration: sudo cat /etc/nginx/sites-available/sitename.conf
  3. Check for typos in file paths

Issue: Wrong site showing
Solution:
  1. Check DNS is pointing to correct server
  2. Verify server_name in site configuration
  3. Check no conflicts with other sites

HTTPS/SSL WITH LET'S ENCRYPT
-----------------------------
To add HTTPS to a site:

1. Install Certbot:
   sudo apt install certbot python3-certbot-nginx

2. Obtain certificate:
   sudo certbot certonly --nginx -d yourdomain.com -d www.yourdomain.com

3. Recreate site with SSL:
   sudo manage-site remove sitename
   sudo manage-site add sitename --domain yourdomain.com --ssl

Or use the SSL templates directly:
   sudo cp /etc/nginx/templates/site-static-ssl.conf.template /etc/nginx/sites-available/sitename.conf
   # Edit and replace template variables
   sudo ln -sf /etc/nginx/sites-available/sitename.conf /etc/nginx/sites-enabled/
   sudo nginx -t && sudo systemctl reload nginx

STANDARD NGINX STRUCTURE
-------------------------
This deployment follows standard Nginx conventions:

/etc/nginx/
├── nginx.conf                 # Main Nginx config (global settings)
├── sites-available/           # All site configurations
│   ├── 00-default.conf       # Catch-all default server
│   ├── devhub.conf           # DevHub.sbs
│   └── ...                   # Other sites
├── sites-enabled/             # Enabled sites (symlinks)
│   ├── 00-default.conf → ../sites-available/00-default.conf
│   ├── devhub.conf → ../sites-available/devhub.conf
│   └── ...
└── templates/                 # Configuration templates

/var/www/
├── default/                   # Default page
├── devhub.sbs/docs/          # DevHub website files
└── ...                       # Other sites

/var/log/nginx/
├── access.log                 # Global access log
├── error.log                  # Global error log
├── devhub-access.log         # Per-site logs
└── devhub-error.log
